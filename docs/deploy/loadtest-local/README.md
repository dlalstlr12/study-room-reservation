# 로컬 부하테스트 원본 로그 (2026-09-15 재실행)

`docs/performance.md`의 로컬 수치는 개발 중 여러 시점에 잰 값을 표로 옮겨 적은 것이라,
직접 실행한 raw 터미널 출력이 저장소에 없었다. 포트폴리오에 "말로만 그렇게 했다"는
의심이 들 수 있다는 지적을 받고, 같은 스크립트를 다시 돌려 이번엔 raw 로그를 그대로 커밋했다.

| | |
|---|---|
| 날짜 | 2026-09-15 |
| 머신 | 로컬 개발 PC (Windows), Docker Desktop |
| 인프라 | MySQL 8.0 · Redis 7 · Kafka 3.8 (`docker compose up`) |
| 백엔드 | `java -jar` (bootJar), `local` 프로파일, `--logging.level.root=WARN` |
| 부하 도구 | `docker run --rm -i grafana/k6 run -` (BASE_URL=host.docker.internal:8080) |

`ranking-read.txt`, `subscription-read.txt`, `notification-announce.txt`.

## 관찰 — 절대 수치는 이번에도 흔들렸다, 패턴은 그대로다

- **오버부킹 10 → 1 은 재현되지 않았다.** `none` 전략에서 이번엔 1건만 오버부킹됐다.
  `troubleshooting.md`/`performance.md`가 이미 경고한 대로, 오버부킹 건수는 **처리량(=race
  window 크기)에 비례**한다. 이번 머신이 그때보다 느렸거나(548 vs 761 req/s), 다른 프로세스
  점유로 커밋 사이 창이 좁았을 수 있다 — 원인을 하나로 못 박을 수는 없다. **"항상 정확히
  10건 재현된다"는 주장은 원래도 하지 않았고, 이번 실행이 그걸 다시 확인해줬다.**
- **정합성 보장(비관적 락/분산 락 → 정확히 1건)은 이번에도 완벽히 재현됐다.** 이건 타이밍에
  의존하지 않는 결정적 결과라 신뢰할 수 있는 부분이다. 같은 결론은 CI에서 매번 도는
  JUnit 동시성 테스트(`reservation/concurrency/`)가 훨씬 엄격하게 보장한다 — 고정 스레드 수로
  같은 단정을 매 push마다 확인한다.
- **캐시 효과(4.4~4.5배)는 두 실행 모두 거의 동일하게 재현됐다.** 이건 타이밍 레이스가 아니라
  구조적인 차이(쿼리 스킵)라 안정적으로 재현된다.
- **결론은 원래 문서와 같다: 절대 수치는 측정 시점·머신 상태에 종속되고, 신뢰할 수 있는 건
  같은 실행 안에서의 상대 비교다.** 이번 raw 로그는 그 주장을 검증 가능한 형태로 한 번 더
  보여준다.

## 알림 팬아웃 (0.3 장애율 → 최종 실패율)

문서의 원래 조건(5건/초 × 30초, 회원 430명 ≈ 6만4천 건)을 그대로 돌려봤더니 컨슈머
동시성 1 처리량(로컬에서 실측 ~43 msg/s)으로는 드레인에만 15분 이상 걸려 세션 안에
끝까지 지켜보기 어려웠다. 그래서 **RATE=1(초당 1건, 30초 동일)**로 낮춰 다시 실행했다 —
공지 31건 × 회원 513명(이전 부하테스트가 만든 로드테스트 계정 포함) = 15,903건.

첫 시도는 DB의 `notifications` 행만 지우고 재실행했는데, 이전 실행(5건/초 조건)이 Kafka
토픽에 남긴 처리 대기 메시지까지 같은 컨슈머가 계속 소비하면서 숫자가 15,903을 한참
넘어서까지 안 멈췄다 — **DB를 비우는 것과 Kafka 백로그를 비우는 것은 다른 일**이라는
걸 실제로 겪었다. `docker compose rm -f kafka && docker compose up -d kafka`로 브로커를
통째로 새로 띄워(볼륨 없어 완전 초기화) 다시 한 번 클린하게 실행했다.

## 결과 — 알림 최종 상태 (완전 드레인 확인)

| status | 건수 |
|---|---|
| SENT | 15,791 |
| FAILED | 112 |
| **합계** | **15,903** |

최종 실패율 = 112 / 15,903 = **0.70%**. 문서의 이론값(`0.3⁴ ≈ 0.81%`)과 가깝다 —
N=15,903에서 0.81% 기대치는 약 128.8건, 표준편차 약 ±11.3건이므로 112건은 통계적으로
정상 범위(약 1.5σ) 안에 있다. 재시도 체인(0.5s → 1s → 2s 백오프 후 DLT)이 설계대로
동작함을 완전히 드레인된 실측으로 확인했다.
